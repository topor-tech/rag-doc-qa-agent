# Что добавить в поиск

Каталог и лексический BM25 по леммам уже работают (`specs/specs/knowledge.md`). Ниже то, что этот поиск всё ещё не закрывает.

## Заголовок перебивает пункт

`rewrite_query` может вернуть строку, которая копирует заголовок раздела. Заголовок входит в мешок BM25 три раза, поэтому каждый пункт этого раздела обгоняет более точный пункт другого раздела. Для вопроса про расчёт полугодовой давности переписывание подняло раздел 13 («Проверка и актуализация расчетов») выше пунктов 8.2–8.3, где как раз сказано про шесть месяцев.

Переписывание вопроса стоит оставить, но совпадение с заголовком не должно поднимать порог отсечения для остальных пунктов.

## Парафраз без общих слов

Лемма сводит формы одного слова (`ставки` / `ставок` → `ставка`, `ё` схлопывается). Разные слова она не соединяет: `полгода` и `6 месяцев` остаются разными термами.

Плотный вектор по тем же строкам `clauses` связал бы такие пары. Колонки `pgvector` на этом Postgres достаточно. Два списка — лексический и векторный — нужно смешивать так, чтобы одно сильное совпадение заголовка не поднимало пол для второго списка.

`clauses.search_vector` и GIN по `lemma_text` уже пишутся при загрузке и ранжированием не читаются. Их можно использовать в эксперименте, не заводя вторую базу.

## Поиск в читалке

`GET /documents` отдаёт оглавление. Отдельного поиска по каталогу в интерфейсе нет. Тот же `search_sections`, что у MCP, может отвечать на `GET /documents/search?q=` и открывать `/kb/{document_id}#s-{section_id}`.
